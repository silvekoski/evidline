# Build spec

Read PRD.md and .planning/decisions.md first. This file is the contract between the packages. The types in `packages/schemas/src` are the law. Do not change a schema without a note in your result.

## Conventions

- TypeScript, ESM, `moduleResolution: bundler`. Import inside a package with relative paths and no extension. Import another package by name: `@tpm/schemas`, `@tpm/core`.
- Do not add dependencies and do not run `pnpm install`. If you need a package, report it.
- Tests: Vitest, in `test/*.test.ts` of each package. Run `pnpm --filter <pkg> test` and `pnpm --filter <pkg> typecheck`. Root `pnpm lint` must pass. The lint config blocks network access outside `packages/egress` and all I/O in `packages/core`.
- No comments unless the code cannot say it. Prose in files and results follows CLAUDE.md.
- Every number in evidence stats, trace stats and inference values is a finite number. A ratio with a zero denominator is 1 and its check passes. Use `NaN` only inside `Float64Array` series for a missing value.
- Deterministic: no `Math.random()`. `packages/core/src/random.ts` exports `mulberry32(seed)`.
- Every claim is an inference with at least one evidence id. Evidence comes first, then the inference that cites it.
- Units. Every window, onset, lag, duration and window size is in grid samples. `maxRate` is sensor units per sample. Text that leaves the plant (trace results, evidence verdicts, claims) names sample indexes, never an absolute time. The UI converts samples to days with the run time base.
- Lag sign. `lag > 0` means `a` leads `b` by `lag` samples: `b[t]` follows `a[t - lag]`. A `Relation` stores `a` before `b` in alias order. A `Peer` of sensor `x` has `lag > 0` when the peer leads `x`, so the aligned peer value at `t` is `peer[t - lag]`.
- Episode boundaries. `Grid.episodes` lists the episodes. First differences, run lengths, Hampel windows, cross-correlation alignment and CUSUM sums never cross a boundary (CUSUM restarts at 0). A change point within max(2, 0.1% of n) samples of a boundary is dropped. The baseline end snaps to the nearest earlier boundary when one lies within 5% of n.
- NaN rules for stats primitives: `cusum` holds its sums over NaN, `theilSen` and `mannKendall` drop NaN points, `spearman` and `crossCorrelation` use pairwise complete samples and report `n`, `quantile` and `mad` skip NaN. Every primitive returns finite numbers or `null`, never NaN.

## packages/core

Pure functions. No `node:` imports. Exports from `src/index.ts`.

```ts
export type Grid = {
  aliases: string[];          // "S01", "S02", ... column order
  values: Float64Array[];     // one per alias, length n, NaN = missing
  n: number;
  dt: number | null;          // ms per grid sample, null without a time column
  time: Float64Array | null;  // ms per grid row (bucket start), null without a time column
  episodes: Window[];         // at least one, covers [0, n)
};
export type Masks = Uint8Array[];   // one per alias, length n, 1 = masked by the health gate

export type EvidenceInput = Omit<Evidence, "id" | "runId">;
export type EvidenceSink = {
  add(e: EvidenceInput, derived?: Record<string, Float64Array>): string;   // returns the evidence id
};
export function createMemorySink(runId: string): EvidenceSink & { evidence: Evidence[]; derived: Map<string, Record<string, Float64Array>> };
```

Core never sees `t0`. Evidence ids are `ev-<runId>-<counter>` with a zero-padded 5-digit counter; `runId` is 8 lower-case hex characters. Derived series (`expected`, `deviation`, `distance`) have grid length and are referenced from a chart spec as `{ derived: "<key>" }`. A `lag` chart fills `ChartSpec.lags` and marks the best lag with a mark of kind `best-lag`.

Every stage result carries `claim: string` (numbers at 3 significant digits, sample indexes for positions), `confidence`, `evidenceIds`, plus the stage `value`.

### Stage functions

| Function | Output | Evidence |
| --- | --- | --- |
| `fingerprint(x, episodes)` | `Fingerprint` | none |
| `selectBaseline(grid, fps, sink)` | `{ value: BaselineValue; claim; confidence; evidenceIds }` | one `changepoint` evidence per sensor with change points, one `structure` evidence for the chosen window |
| `calibrateHealth(grid, baseline, fps, sink, seed)` | `{ thresholds: Partial<Thresholds>; value: CalibrationValue; claim; confidence; evidenceIds }` | one `calibration` evidence with a bar chart of the detection table |
| `healthGate(grid, baseline, fps, thresholds, sink)` | `HealthResult[]` = `{ value: HealthValue; claim; confidence; evidenceIds; mask: Uint8Array }` per sensor | one `health` evidence per failed check, one per healthy sensor with all check statistics |
| `proposeRules(grid, baseline, fps, thresholds, sink)` | `RuleResult[]` = `{ value: RuleValue; claim; confidence; evidenceIds }` | one `rule` evidence per rule with the baseline violation count |
| `relationGraph(grid, masks, health, baseline, fps, thresholds, sink)` | `RelationGraph` = `{ relations: Relation[]; groups: RedundancyGroup[]; flowOrder: string[]; peers: Map<string, Peer[]> }`, `Peer = { alias; lag; rho; n }` | one `correlation` evidence per kept pair, one `lag` evidence per directed edge, one `structure` evidence per group and one for the flow order |
| `scoreRoles(grid, fps, graph, baseline, sink)` | `RoleResult[]` = `{ value: RoleValue; claim; confidence; evidenceIds }` | one `distribution` evidence per sensor from the fingerprint, plus the relation evidence it used |
| `calibrateDrift(grid, masks, graph, baseline, fps, sink, seed)` | same shape as `calibrateHealth` | one `calibration` evidence |
| `detectDrift(grid, masks, graph, roles, baseline, fps, thresholds, sink, overrides)` | `DriftResult[]` = `{ value: DriftValue; claim; confidence; evidenceIds; model: PeerModel | null }` | `residual` evidence with derived `expected` and `deviation`, `trend` evidence, `changepoint` evidence for the onset, `distribution` evidence with derived `distance` for the no-peer path |
| `separateFaults(ctx, sink, overrides)` | `Incident[]` = `{ value: DiagnosisValue (prose null); claim; confidence; evidenceIds }` | `structure` evidence for the PCA statistics and contributions, `lag` evidence for onset order |
| `runPipeline(grid, sink, options)` | `PipelineResult` | runs every stage in order and reports `onStage(name: StageName, ms, counts)` |

`PipelineOptions = { seed?: number; overrides?: Overrides; onStage?: (name: StageName, ms: number, counts: Record<string, number>) => void }`. `Overrides` is the schema type: `baseline`, `roles` by alias, `masked` aliases, `faultClass` keyed by the incident lead sensor (`ranked[0].sensor` or the health-failed sensor), `responsible` keyed by the drifting sensor. An incident takes the `faultClass` override whose key is in its ranked list or is its excluded sensor.

Order in `runPipeline` (the `StageName` values after "Source adapter"): Fingerprint, Baseline, Health calibration, Health gate, Rule proposals, Relation graph, Role scoring, Drift calibration, Drift detector, Fault separation. The server adds "Model calls".

Confidence: roles = best minus second best, times (1 - missingRate); health = clamp(|log2(statistic / threshold)|, 0, 1) for the decisive check; drift = clamp(maxDeviation / deviationLimit - 1, 0, 1); diagnosis = 1 for a health row, 0.9 for the redundancy row, else clamp(|spe / speLimit - t2 / t2Limit|, 0, 1); baseline = share of sensors with no change point inside the window; rules and calibration = 1.

### Algorithms

Follow PRD section 5. These details fill the gaps.

- Fingerprint. Quantiles by sorting a copy without NaN. MAD scaled by 1.4826. `hold` = the mode of run lengths when runs of that length cover more than 80% of samples, else 1. When `hold > 1`, compute noise, step, flatShare, Hampel outliers, run lengths and the resolution step on the run-compressed series (one value per run). Noise = MAD of first differences divided by sqrt(2). Step = smallest positive difference between distinct sorted values (cap the distinct scan at 100,000 values). Histogram = 18 equal-width bins between p1 and p99 plus one edge bin below p1 and one above p99: 20 shares, 21 edges. acfTime = first lag where the autocorrelation falls below 1/e, searched up to n/4 on a copy of at most 8,192 points, scaled back to grid samples. Period from the largest autocorrelation peak after the first zero crossing, or null. flatShare = share of samples inside runs of 3 or more identical values (after hold compression). monotonicShare = |sum of sign(diff)| / count of nonzero diffs. Signal type: constant if distinct = 1, binary if distinct = 2, state if distinct <= 8 and flatShare > 0.9, counter if monotonicShare > 0.98, step if flatShare > 0.6, slow if acfTime > 20, else fast.
- Scale floors. sigma of a residual = max(1.4826 MAD(residual), step). The change point scale of a sensor = max(MAD, noise). The distance path uses the same floor for the baseline MAD.
- Baseline. Change points by binary segmentation on the mean with a BIC penalty, on a downsampled copy of at most 4,096 points, mapped back to grid indexes, boundary-dropped per the episode rule. A change point counts when 3 or more sensors share it (within 1% of n) or one sensor moves more than 3 change point scales. Baseline = [0, first counted change point), snapped to an episode boundary. Minimum length = max(1000, 10% of n); skip an earlier change point. With no change point, the baseline is the first 60% of the grid.
- Health gate. Blocks of size w = clamp(n / 64, 64, 1024), non-overlapping, never crossing an episode boundary. Each check compares the block with the baseline statistics of the same sensor. Failed blocks merge into windows. Checks in PRD order, and the first failed check in that order is the sensor's health class: dropout = block missing rate against dropoutRateFactor x baseline missing rate (floor 0.01); dead = longest run (in hold units) against deadRunFactor x baseline p99 run length; stuck = block noise against stuckNoiseRatio x baseline noise; spikes = share of Hampel outliers (window 7, spikeSigma MAD) against max(0.02, spikeShareFactor x baseline share); saturated = share of values at the baseline p1 or p99 edge value against max(saturationShare, 3 x baseline edge share), only when the baseline has at least 20 distinct values; noisy = block noise against noisyRatio x baseline noise; timebase = any step in `grid.time` inside the block that is <= 0 or outside [timebaseTolerance x dt, dt / timebaseTolerance], passes without `time`; resolution = block step against resolutionFactor x baseline step or baseline step / resolutionFactor. A sensor that is constant in the baseline is dead everywhere and masked everywhere. Each `HealthValue.checks` entry carries the block statistic (max over blocks) and its threshold.
- Rule proposals. Per continuous sensor (signal type slow or fast): a `range` rule (min = p1 - 3 MAD, max = p99 + 3 MAD), a `flatline` rule (maxDuration = deadRunFactor x baseline p99 run length x hold) and a `missing` rule (maxMissingRate = max(0.05, dropoutRateFactor x baseline missing rate), windowSize = w). Each rule's `source` is its restated sentence. Violations are counted on the whole grid.
- Relation graph. Rank each sensor once on the baseline (NaN where masked or missing), then Pearson on jointly valid ranks per pair. Keep pairs with |rho| >= relationRho. Cross-correlation for kept pairs on a baseline copy of at most 8,192 points and lags -32..32 in that copy; scale the best lag back to grid samples. A directed edge exists when the best lag is not 0 and rhoAtLag exceeds |rho| at lag 0 by 0.02. Redundancy group = connected components over pairs with |rho| >= redundancyRho at lag 0. Flow order = Kahn topological sort over directed edges, ties by alias; a cycle breaks at its weakest edge. Peers of a sensor = up to 5 kept pairs with the largest |rho|, excluding every sensor with a failed health check anywhere in the grid.
- Roles. Score each role from 0 to 1 with the evidence in PRD 5.5. `scores` holds all nine roles; an unscored role is 0. Actuator without a setpoint: the sensor leads at least one sensor with |rho| >= 0.5 and has a lag-0 partner with |rho| >= 0.95 whose baseline range (p99 - p1, relative to MAD) is narrower; that partner scores controlled. Role "unknown" if the best score < 0.3. Constant sensors are "unknown".
- Drift, peer path. Robust linear regression of the sensor on its lag-aligned peers on the baseline, Huber weights, 5 iterations, solved with ml-matrix. sigma per the scale floor. Deviation = residual / sigma on the full grid, NaN where the sensor or a peer is missing. Block medians of the deviation with block = max(1, floor(n / 200)) samples (or one day when dt is known and a day holds at least 20 samples). Verdict: drifting when maxDeviation = max |block median| after the baseline >= deviationLimit and (Mann-Kendall p < 0.01 on the block medians or CUSUM alarms). Two-sided CUSUM with k = cusumK and h = cusumH on the deviation, started at the end of the baseline, restarted at episode boundaries; it locates the onset: the last index where the alarming side was zero before the crossing; detectionDelay = alarm index - onset. Theil-Sen slope (ratePer1000 = slope per 1000 samples) and Mann-Kendall Z with p-value from the normal approximation. Severity = maxDeviation / deviationLimit. inRange = the median of the last block lies inside baseline p1..p99. Responsible: leave-one-out over the peer set; responsible = the sensor when every peer's own deviation (from a model without this sensor) has max |block median| < deviationLimit, else null. A drifting sensor whose deviation falls below deviationLimit when the responsible sensor is removed from its peers is a victim of that sensor.
- Drift, no-peer path. Distance = Wasserstein-1 between a window of size w = clamp(n / 40, 200, 5000) and the baseline distribution, divided by the baseline scale, evaluated at stride floor(w / 4). Standardize by the median and MAD of the distance over baseline windows. Run the same CUSUM and trend tests on that series and map the onset back to grid samples. deviationLimit applies to the standardized distance.
- Fault separation. Health failures become one incident per sensor with the class from `healthToFault`. Drivers are drifting sensors that are not victims. Drivers group into incidents when they share a kept pair and |onset difference| <= max(2 acfTime, 1% of n). Victims appear in the ranked list of their driver's incident. Each incident runs the PRD 5.7 table in order. Data fault when 80% or more sensors have a change point at the same index (episode boundaries excluded). Bias against gain: |Spearman(deviation, expected)| > 0.5 on the post-onset window means gain. Control loop rows use the roles: a controlled variable whose deviation from its setpoint or partner stays flat while an actuator that leads it drifts. Process fault kind, tested in this order: slow degradation when the |deviation| block medians have a significant monotone Theil-Sen trend (Mann-Kendall p < 0.01) over at least 4 blocks; step when the deviation jumps more than 2 within 2 acfTime samples at the onset; oscillation when the deviation autocorrelation shows a period with a peak > 0.5; else degradation. PCA on the healthy baseline with `new PCA(rows, { center: true, scale: true })` over non-constant, health-passed sensors, components that explain 90% of the variance; T2 and SPE limits = baseline p99 times 1.5; contributions from scaled SPE per sensor when SPE exceeds its limit, else from T2 loadings; onset order breaks ties. Masked sensors are in `excluded` and never in `ranked`. Ranked contributions sum to 1. The incident window runs from the onset (or the first masked window) to the end of the grid and has at least 100 samples.
- Trace. Steps in this order: health, drift, isolation, propagation, control-loop, verdict. Each step has `n` (samples the test used), stats, a result sentence with numbers at 3 significant digits, and evidence ids that exist. Every key in a step's stats also exists with the same value in the stats of one of its cited evidence. The health step names every excluded sensor and its health class. The verdict step cites the evidence of the decisive table row.
- Health calibration. Split the baseline into K = clamp(floor(baseline length / 500), 4, 20) segments. Inject on copies: a flatline, spikes at 6 sigma every 50 samples, noise x3, dropout 20%, a 10% gain step, a resolution change x4. Grid search deadRunFactor in {3, 5, 10, 20}, stuckNoiseRatio in {0.05, 0.1, 0.2}, spikeSigma in {4, 5, 6, 8}, noisyRatio in {2, 3, 5}. Pick, per parameter, the smallest value with false alarms on clean segments at or below 1% of segment-sensor pairs. When no value meets the target, take the largest and report the achieved rate. Fixed: spikeShareFactor 3, resolutionFactor 4, timebaseTolerance 0.5, dropoutRateFactor 5, saturationShare 0.05, redundancyRho 0.95, relationRho 0.3, deviationLimit 3.
- Drift calibration. On held-out segments: fit the peer model on the other segments, inject into the sensor a bias ramp that reaches 0.5, 1, 2, 4 and 8 residual sigma at the segment end, and a 10% gain ramp, recompute the deviation and the distance path. Grid search cusumH in {5, 10, 20, 50, 100, 200} with cusumK in {0.5, 1}; distributionLimit the same way on the standardized distance. Count a false alarm per clean segment where the verdict rule fires. Pick the smallest h with false alarms <= 1% of segment-sensor pairs, else the largest with the achieved rate. The detection table reports each fault with detected and delay in samples.
- Fault injection: `injectFault(x, spec, rng)` with `FaultSpec = { kind: "bias" | "gain" | "dead" | "spikes" | "noise" | "dropout" | "step" | "resolution"; from: number; to?: number; magnitude: number }`. Bias and gain ramp linearly from `from` to `to` (or the end); magnitude for bias is in sensor units, for gain a factor, for dead the held value is the value at `from`.

quantile, mad, hampel, cusum, theilSen, mannKendall, spearmanRanks (rank once) and pearson, crossCorrelation, robustRegression (Huber IRLS), binarySegmentation, wasserstein1, autocorrelation, runLengths, histogram, downsample (bucket mean), roundSig(x, 3).

## packages/adapters

```ts
export type SourceStats = { rows: number; columns: number; rawBytes: number; quarantined: string[]; domain: Domain; bucket: number; episodes: number };
export type Source = { grid: Grid; t0: number | null; sourceNames: string[]; stats: SourceStats };
export function detectLayout(sample: string[][], header: string[]): { domain: Domain; timeColumn: number | null; counterColumn: number | null };
export async function loadSource(path: string, opts?: { maxGrid?: number; onProgress?: (rows: number) => void }): Promise<Source>;
```

- `loadSource` streams the file with csv-parse. It reads the first 5,000 rows for layout detection, then streams once more for the full load. When the sample shows plain decimals only, use a fast path: split on `,` and `Number`.
- Stream layout: numeric columns become sensors. The time column (ISO text, or seconds or ms since epoch) sets `t0`, `time` and `dt` = median step x bucket. A `+1` counter column with resets marks episodes and is not a sensor. Columns constant inside every episode are quarantined. Text columns are quarantined. `sourceNames[i]` is the original header of alias i.
- Downsampling: bucket = the smallest power of 2 with rows / bucket <= maxGrid (default 262,144). Bucket mean skips NaN; a bucket with all NaN is NaN. Episode boundaries map to bucket indexes. `time` holds the bucket start.
- Records layout: profile fields as timestamp, id, number, category or text on the sample. Choose the bucket from [1 min, 5 min, 15 min, 1 h, 2 h, 4 h, 6 h, 12 h, 1 d, 7 d] as the smallest with median rows per bucket >= 100. Derive the metrics in PRD section 10 as sensors. Source names are `field.metric` and `field.metric[category=value]` for splits. Split only category fields with at most 12 levels. Cap at 200 sensors, largest relative variance first.
- `parseNumber` accepts `1,5`, `1.5` and `1 234,5`, returns NaN for empty and non-numeric text.

## packages/egress

```ts
export type Provider = ProviderInfo & { call(payloadText: string, template: string, schema: ZodType): Promise<string> };
export type EgressStore = { write(record: EgressRecord): void; update(id: string, patch: Partial<EgressRecord>): void };
export type LeakIndex = { has(triple: [number, number, number]): boolean; names: string[]; size: number };
export function buildLeakIndex(raw: { alias: string; values: Float64Array }[], forbidden: string[]): LeakIndex;
export function scanForLeaks(payloadText: string, index: LeakIndex): { valueHits: number; nameHits: number; detail: string };
export function createGateway(opts: { store: EgressStore; getSettings: () => ModelSettings; getProvider: (mode: ModelMode) => Provider | null; leakIndex: (runId: string | null) => LeakIndex; nowIso: () => string; newId: () => string }): Gateway;
export type Gateway = {
  call<T>(purpose: Purpose, payload: EgressPayload, ctx: { runId: string | null; inferenceId: string | null; operatorText: boolean }): Promise<{ ok: true; value: T; recordId: string; source: "model" | "fallback" } | { ok: false; recordId: string | null; reason: string }>;
  templates(): TemplateInfo;
};
export const templates: Record<Purpose, string>;
export function fallback(purpose, payload): unknown | null;
export function validateProse(sentences: { text; evidenceIds }[], ctx: { evidence: Evidence[]; aliases: string[]; faultClass: FaultClass }): ProseValidation;
export function roundPayload(value: unknown): unknown;
```

- Guards in PRD order, run in every mode: schema (`EgressPayload`), floor (every key named `n` at any depth >= 100), size (arrays of numbers <= 20, payload <= 8 KB), rounding (3 significant digits on non-integer numbers; integers stay exact), leak (values), names, record. A failed guard writes a `blocked` record and returns `ok: false`. Mode `off` writes an `off` record with the payload and returns the fallback value (`source: "fallback"`) or `ok: false` when the purpose has no fallback.
- The gateway serializes once after rounding, scans that string, writes it to the record verbatim, and the provider embeds that string unchanged in the user message. The record's `payload` equals the bytes that left.
- Leak index: per run, round every raw series to 3 significant digits, collapse consecutive repeated values (a sample-and-hold sensor becomes one value per hold), and hash every triple of consecutive values across every sensor. The scanner collapses repeated consecutive tokens the same way before it forms triples into a sorted `Float64Array` (or a `Set` of string keys when the grid is under 100,000 points). `scanForLeaks` extracts all number tokens from the payload text, forms every run of 3 consecutive tokens, and looks them up. `names` holds the forbidden strings (source names, quarantined column names, file name stem, category values) and the scanner searches for each string of 3 or more characters, case-insensitive, at word boundaries. Any hit blocks the call and counts in `hits`.
- Providers: `openai` (OpenAI-compatible chat completions, the default for mode `cloud` when `TPM_OPENAI_URL` and `TPM_OPENAI_KEY` exist) posts to `TPM_OPENAI_URL` with a Bearer key, `model` = `TPM_OPENAI_MODEL`, `response_format` json_schema strict, temperature 0. `azure` uses `POST {host}/openai/deployments/{model}/chat/completions?api-version=2024-10-21` with `response_format: { type: "json_schema" }` and the header `api-key`. `ollama` uses `POST {host}/api/chat` with `format` = JSON schema and `stream: false`. Config from `process.env`: `TPM_AZURE_ENDPOINT`, `TPM_AZURE_KEY`, `TPM_AZURE_DEPLOYMENT`, `TPM_AZURE_REGION`, `TPM_OLLAMA_HOST`, `TPM_OLLAMA_MODEL`. The host comes from the environment only. Responses parse with the response schema; a parse failure returns `ok: false` with an `error` record.
- Templates: four constant strings with no dataset text. Each names the unit (grid samples, `dt` ms per sample when present) and the response schema. `templateHash` = sha256 hex of the template.
- Fallbacks. `name_role`: null (no hypothesis). `explain_diagnosis`: one sentence per trace step from `result`, each with the step's evidence ids, plus a first sentence with the fault label from `faultLabel`. `compile_rule`: a grammar with one regex per rule type, durations in minutes, hours, days or samples converted with `dt`: `S07 must not stay flat for more than 10 minutes`, `S03 must stay between 10 and 20`, `S03 must stay below 20`, `S03 must stay above 10`, `S03 must not change faster than 5 per sample`, `S03 must track S04 within 2`, `S03 must not be missing more than 5% in 1 hour`, `mean of S03 over 1 hour must stay below 20`. No match returns `ok: false` with the reason "sentence not understood, model off" and the UI lists the accepted forms. `plan_investigation`: by stage: role -> `test_role` with the current role plus `compare_windows` of the baseline against the rest; drift -> `find_changepoints` near the onset with span 2% of n plus `rerun_without` the responsible sensor when one exists; diagnosis -> `rerun_without` the top ranked sensor plus `compare_windows` of the baseline against the incident window; health -> `compare_windows` of the baseline against the first masked window; baseline -> `find_changepoints` near the baseline end. A number in the question that reads as a sample index, a day or a week (with `dt`) centers `find_changepoints` there.
- Validator per PRD 5.8: every sentence cites at least one evidence id from the incident; every number in a sentence (after removing alias and evidence id tokens) equals a stat of the cited evidence at the sentence's digit count (at most 3 significant digits); every alias exists; the fault label from `faultLabel` appears once. Template prose is always shown; its validation result is recorded, not gated.

## apps/server

- Hono on port 8787. Routes under `/api`: `GET /files`, `POST /files` (raw body, header `x-file-name`, streamed to `data/uploads/<sanitized name>`, returns `FileEntry`), `POST /runs` (`CreateRunBody`, path relative to `data/`, resolved and rejected outside it with 400), `GET /runs`, `GET /runs/:id`, `GET /runs/:id/events` (SSE), `GET /runs/:id/sensors`, `GET /runs/:id/sensors/:alias`, `GET /runs/:id/quality`, `GET /runs/:id/drift`, `GET /runs/:id/incidents`, `POST /runs/:id/model-calls`, `GET /evidence/:id`, `GET /evidence/:id/series`, `GET /inferences/:id`, `GET /inferences/:id/thread`, `POST /inferences/:id/accept|question|override`, `POST /rules/compile`, `POST /rules/:id/activate`, `GET /log?runId=`, `GET /log/verify`, `GET /log/export?format=json|csv`, `GET /egress?runId=`, `GET /egress/totals?runId=`, `GET /egress/templates`, `GET /egress/:id`, `GET|PUT /settings/model` (PUT body `ModelModeBody`). In production it serves `apps/web/dist` and falls back to `index.html`.
- `runId` = 8 lower-case hex characters from `crypto.randomBytes`. Never from the file name, the path or the time. Inference ids `inf-<runId>-<5 digits>`, thread ids `th-...`, egress ids `eg-...`, rule ids `rule-...`.
- SQLite in `data/tpm.db`, WAL mode. Tables: runs, sensors, grids (run_id, alias, values blob), evidence, evidence_series (evidence_id, key, values blob), inferences, rules, threads, log, egress, settings. JSON columns as text.
- The pipeline runs in a worker thread (`src/pipeline-worker.ts`): `loadSource`, then `runPipeline` with a memory sink; it posts stage progress and returns the result. The main thread persists everything, then runs the "Model calls" stage through the gateway: `name_role` per sensor (concurrency 4) and `explain_diagnosis` per incident, then writes the log entries.
- Payload builders. `name_role`: `SensorSummary` from the fingerprint, role and peers (`leads` and `follows` from directed edges, `n` = pair sample count). `compile_rule` catalog: aliases named in the sentence first, then the rest by role confidence, at most 20. `plan_investigation` catalog: aliases in the question, the inference's sensor, its peers and redundancy group, then flow-order neighbors, at most 20. `explain_diagnosis`: top 20 ranked renormalized to sum 1, the rest moved to `excluded` (at most 20), `n` = incident window length. Sensor aliases in a `RuleJson` or `ToolCall` that are not in the run give HTTP 422.
- SSE streams `RunEvent` objects. A subscriber that connects after the run finished gets the final `run` event and `done`.
- Decision log: serialize the entry with keys in `LogEntry` order (seq, time, type, actor, runId, inferenceId, evidenceIds, egressId, before, after, reason, prevHash), store that JSON text in the row, `hash = sha256(prevHash + text)`. The first `prevHash` is 64 zeros. `/log/verify` hashes the stored text. Export as JSON or CSV.
- Accept sets status `accepted` and writes the log entry. Every rerun builds `Overrides` from all accepted and overridden inferences of the parent run: role, baseline, faultClass, responsible, plus `masked` from `rerun_without`.
- Question: build the payload, call the gateway, clamp every returned window to [0, n), run the tool calls in the plant with core functions, attach evidence, then the verdict: revise when a `rerun_without` or `test_role` result changes the inference value (role, faultClass, responsible, or onset by more than 1% of n): create a new inference with `supersedes`, mark the old one `revised`, return it in `changed`; else confirm and set `accepted`.
- Override: store, write the log entry, run `runPipeline` again with the overrides as a child run (`parentRunId`), create new inferences with `supersedes`, mark the old ones `overridden`, return `changed` (inferences whose value differs by stage and sensor).
- `PUT /settings/model` switches the mode. A switch to `local` or `cloud` then runs `POST /runs/:id/model-calls` for the newest run whose records are `off`; new inferences supersede the old ones.
- Totals: `sentBytes` = sum of `payloadBytes` over status `sent` or `error`; `calls` = all records; `scannerHits` = records where the `leak` or `names` guard failed; `rawBytes` = sum of `Run.rawBytes`; `hosts` = distinct provider hosts of sent records.
- `notes` on a sensor = question texts and override reasons for the same alias from this run, its parent chain and every run with the same `name`, newest first, as `<date> <actor>: <text>`.
- `GET /evidence/:id/series` returns the grid values of the chart series inside the evidence window, downsampled to at most 2,000 points, plus derived series. `t` holds grid indexes.

## scripts

- `scripts/build-demo.ts <input csv> [out]`: reads the TEP file (the full file or `data/tep-subset.csv`), keeps test episodes of fault 0 runs 1..20 and then fault 13 run 1, writes `data/demo-stream.csv` with columns `time` (3 min steps from 2026-01-01T00:00:00Z), `sample` (the episode counter, quarantined by the adapter), and the 52 sensor columns with their original headers. Injects after 60% of the rows: a slow bias ramp on a sensor with at least 3 peers at |rho| >= 0.5 that reaches at least 6 residual sigma at the end and stays inside the baseline p1..p99, and a dead sensor outside that sensor's peer set. Writes `data/demo-stream.truth.json` with the injected faults and the fault 13 onset row. The app never reads the truth file.
- `scripts/build-demo-records.ts`: writes `data/demo-records.csv`, synthetic web shop orders, about 150 rows per hour over 60 days: `time, orderId, terminal (8 values), postcode, city, net, tax, gross, note`, seeded. Injects at row level: `postcode` null from day 40, terminal `T3` sends cents from day 35, the `note` typo rate ramps from day 20, the row count drops 30% from day 50 with basket value and conversion moving with it. Writes `data/demo-records.truth.json`.
- `scripts/canary.ts`: builds a seeded synthetic grid (8 sensors x 20,000 samples, random walks with unique values), runs `runPipeline` and every gateway purpose with a capturing provider, and asserts: every record has status `sent`, zero scanner hits, no payload text contains any triple of consecutive rounded values, any source name, the file stem, the run name or an ISO date; plus a negative case where a planted triple and a planted source name each produce a `blocked` record. Exit code 1 on any failure.

## Integration notes (added 2026-09-19 after the foundation agents)

- `DriftValue.drifting` is the verdict flag. The UI never derives the verdict.
- The residual evidence chart sets `ChartSpec.threshold` = deviationLimit and puts the deviation in `secondary` with key `deviation`. Series keys: `value` for the sensor, `expected`, `deviation`, `distance`.
- `SensorDetail.evidenceIds` lists the role evidence, the distribution evidence, the correlation evidence of the kept pairs and the lag evidence of the directed edges of that sensor.
- SSE: each `data:` line carries one whole `RunEvent` JSON object as a default message event. The client closes on `done`.
- `GET /evidence/:id/series` keys `series` by `ChartSeries.key`.
- Error bodies are `{ error: string }` with the HTTP status.
- `FileEntry.path` is relative to `data/`, so the client passes it straight to `POST /runs`.
- The web app cannot import zod or `@tpm/egress`. Constants the UI needs (the eight rule sentence forms) live in `@tpm/schemas` or are copied.
